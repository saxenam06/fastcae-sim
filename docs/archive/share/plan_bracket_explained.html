An agent that designs brackets, proves them with physics, and learns from every attempt

This page explains the fastcae-sim plan for readers who know LLMs and agents well but not CAD or CAE. Mechanical concepts are translated into AI terms as they come up, and section 0 collects the translations.

  • TaskAn engineer writes a requirement in plain language. The system returns several bracket designs that can be manufactured, each proven against the requirement by physics simulation and explained.
  • EngineAgents run an autonomous data pipeline. They decide what to generate next, invent new design operations, and record every design with its verified physics, including failures and the reasoning behind each change.
  • PayoffThat data trains fast physics models and a fine-tuned design agent. Each round gets faster and cheaper, while the physics simulator stays the final judge.

0CAE in AI terms

CAD is computer-aided design: building the 3D model. CAE is computer-aided engineering: simulating how that model behaves. The rest of this page uses the terms below.

1The problem

  • Brackets are everywhere. Every vehicle, aircraft and machine has many. Each must keep its payload clear of resonance and survive vibration, shock and heat, while staying light, cheap and manufacturable.
  • Today they are designed by hand. Engineers iterate across CAD and simulation tools, explore few concepts, and often find resonance or fatigue problems only in testing. Set-up errors go unnoticed.
  • Off-the-shelf AI doesn't solve it yet. LLMs write CAD that runs but misses the specification. On 12,632 industrial design tasks, nine frontier models writing FreeCAD code reached 57–81 % executability (RealCADBench). Agents that drive simulators often produce results that run but are physically wrong.
  • There's no data to learn from. The public bracket datasets (SimJEB, DeepJEB, DeepJEB++) hold titanium shapes for 3D printing under static loads only. None has vibration, plain-language requirements, design programs or design reasoning.

2What "solved" means

All six must hold.

  • Request → verified brackets. Example requests, plus request types never seen during development, get brackets that pass the manufacturing rules and FE checks for vibration, shock, static load and heat, with margins, assumptions and model validity stated.
  • Physics first. Before designing, the agent states the governing numbers, which requirement binds, and the mechanism. Its hand models are checked against FE with the error measured.
  • An agentic pipeline that earns its keep. At equal compute it beats a scripted pipeline, and the dataset regenerates from one config.
  • Learning that pays off. The physics predictor has a measured false-pass rate on unseen request types, and the trained agent needs measurably fewer rounds or less cost.
  • A real-world anchor. At least three agent designs are made and tap-tested, and the measured first mode is shown next to the prediction.
  • Reproducible claims. Every claim rebuilds from a commit and a config.

3The system at a glance

Three deliverables, all in full

01 · runtimeDesign agent

A request goes in. Verified brackets come out, each with editable CAD, manufacturing files, a verification record and a physics explanation.

02 · offlineAgentic data pipeline

Agents decide what data to create and how. Tested tools build and judge every design. Failures and reasoning are kept.

03 · offlineLearning

Physics AI (fast predictors, embeddings, a design proposer) and a fine-tuned LLM, fed back into 01 and 02.

4The grader: the only authority

Every design passes through the same pipeline: build, check the manufacturing rules, mesh, apply supports and loads, solve, post-process, run physics checks, assign a trust label, then compare against the specification. Version 1 covers natural frequencies, random vibration, fatigue, shock, static g-loads and bolted joints. Heat is an open decision.

LevelModelsCostUsed for
L0Hand formulas: a single mass on a spring, beam and plate formulas, a thermal resistance networkmillisecondsGoverning numbers, screening, which requirement binds
L1FE: modes, random response, fatigue, steady heat conductionsecondsGrading
L2Refined FE, cross-checked with a second solver (CalculiX)minutesThe gold set and the finalists
  • Physics checks on every run: model mass equals CAD mass; a free-floating model has exactly six rigid-body modes; reactions under 1 g equal the weight; effective masses add up to the total; units are consistent.
  • Fault injection: we break inputs on purpose (a units slip, a dropped bolt) and confirm the checks catch every one.
  • Trust labels: each result is VALID, QUESTIONABLE or INVALID. Only VALID results are used for training.
In AI terms

The grader is a verifier built on a physics simulator, and it serves as the reward. L0, L1 and L2 form a cascade of evaluators from cheap to expensive, each with a measured domain where it can be trusted. Physics checks are unit tests for the simulation itself, and fault injection tests those tests. Trust labels are data-quality filters.

5Designs are programs

The agent never draws free-form geometry. Each design is a feature program: a concept, its parameters, and an ordered list of sheet-metal operations. FreeCAD executes the program into an editable model, a STEP file and a laser-ready flat pattern. A mesh and a point cloud are derived from that model for the physics AI.

KindOperations
Structuraladd or remove a flange · side walls · gusset · bead · close the section · change the load path
Thicknesschange gauge · local doubler
Geometrymove a hole · flange length · bend angle and radius · bend relief · lightening hole · hem
Joiningspot-weld, clinch or rivet seam
Isolationisolator mounts at the bolts
  • Where designs come from:
    • even coverage of the parameter space;
    • single edits and combinations of edits;
    • deliberate near-misses and deliberate failures;
    • optimiser paths;
    • agent designs;
    • new operations the agent invents;
    • later, a learned proposer.
  • Beads go where physics says. Stiffening beads are placed where the strain energy of the failing vibration mode is concentrated. This borrows the idea behind topography optimisation, then snaps each bead to one that can actually be formed.
  • Inventions pass a gate. A new operation runs in a sandbox. It is tested on a plain sheet, then on brackets, must pass the manufacturing rules, and needs the engineer's approval. After that it joins the vocabulary, and the pipeline can sweep it like any other operation.
  • Diversity is enforced. A quality-diversity archive (MAP-Elites) keeps the best design of each kind, so the search doesn't collapse onto one shape.
In AI terms

This is program synthesis in a small domain-specific language, with FreeCAD as the interpreter. Agents edit the program's syntax tree through typed tool calls, which keeps every output valid and editable. Inventing an operation is tool creation, guarded by a sandbox, tests and human review. The archive is an open-ended search over behaviour space.

6Agents decide, tools compute

The same five roles work at runtime and in the data pipeline.

RoleAt runtimeIn the data pipeline
Spec agentTurns the request into a typed specification and asks only the questions that block progressWrites requests: paraphrases, incomplete requests, edits, hard cases
Campaign agentPlans the run: concepts, variables, evaluation order, when to stopAs curator, plans each batch from coverage, predictor uncertainty and failures
Design agentPicks concepts and edits, and chooses the strategy: stiffen, move the mass, or isolateDesigns into the gaps. As inventor, writes new operations through the gate
Diagnosis agentExplains each failure from a compact summary and picks the fixAs quality checker, investigates anomalies and quarantined runs
Evidence agentWrites the report: requirement → value → margin → model → assumptionsWrites the dataset card, with evidence for every claim
In AI terms

This is an orchestrator with specialised subagents, using typed tools served over MCP. Standards and manufacturing rules are fetched by retrieval rather than stored in weights, so a rule change needs no retraining. The LLM sees a compact engineering state (hot spots, the dominant mode, the weak joint), never raw FE fields, and it never does the arithmetic.

7The agentic data pipeline

A scripted pipeline samples a fixed plan up front and skips anything that crashes. In this pipeline, agents make the decisions a data engineer would make, in a loop that reads the dataset's own state:

  • Where to sample next. New FE runs go where they teach the most: where the predictor is uncertain, near a pass/fail boundary, where designs are novel, near a promising optimum, or where predictors disagree.
  • How designs are made. Agents design some requests themselves. When no existing operation can reach a region, they invent one.
  • How deep to analyse. Each design gets the cheapest level that is valid for the question. Suspicious results move up a level.
  • What broke. Quarantined runs are diagnosed, and fixes are proposed. Any code change goes through tests and engineer review.
  • The "why". Mechanism, principle and fix are recorded alongside every agent design.
state after batch 2
  coverage   heavy modules (3.5–5 kg) at ≥ 400 Hz: 6 passing designs; most requests unsolved
  predictor  most uncertain on isolated mounts
  failures   19 runs quarantined: 12 rigid-body modes instead of 6

agent decisions for batch 3
  request writer   +200 requests for heavy modules; 50 isolation requests
  curator          70 % of FE time on those regions
  inventor         best box falls 9 % short → writes a double-wall box → gate → FE → joins library
  quality checker  traces the 12-mode runs to a step that moved the module holes → fix → re-run

The agents have to earn their place. At an equal compute budget, the agentic pipeline is compared with a scripted one on five measures: coverage, distinct concepts, predictor error on unseen request types, designs that are both novel and better, and bad labels caught.

In AI terms

It's a data engine combining active learning, curriculum, open-ended search and automated data QA, with agents acting as the data engineers. The scripted baseline is the ablation that shows whether the agents add value.

8The dataset

Each record holds:

  • the request and its paraphrases;
  • the resolved specification;
  • the feature program and the CAD files;
  • the analysis set-up;
  • physics results at each fidelity level;
  • checks, trust label and verdict;
  • lineage (parent, operation, parameters);
  • the agent trace, for agent-made designs.

Here is an example record:

id          B-000417
intent      "Mount a 1.2 kg, 15 W ECU to the vertical body rail, 2×M6 at 80 mm. ISO 16750-3 body.
             First mode ≥ 200 Hz, base ≤ 85 °C. Lightest aluminium."   (+4 paraphrases)
design      closed box · base_flange → side_walls → bend → upright → closed_section(spot weld) → holes
            5052-H32 aluminium, 1.2 mm, 49 g
labels      f1: L0 241 Hz (hand model) · L1 218 Hz · L2 216 Hz
            9.1 g RMS at payload · fatigue damage 0.29 · shock 131 MPa · base 83 °C
checks      all pass · smallest margin +9 % (f1) · trust VALID
trace       1 characterise: mode 1 = upright bending + twist (71 % of strain energy at the root)
            2 concept: twist → close the section   3 add closed_section   4 grade: pass   5 optimise mass
  • Varied requests:
    • complete and driven by stiffness;
    • long overhangs with welding banned;
    • cost-driven, where heat is the binding limit;
    • isolation, the opposite strategy;
    • severe engine-mounted profiles;
    • edits of earlier requests;
    • incomplete requests, where the right answer is questions.
  • Design pairs and deltas: parent → child, failed → repaired, trade-off pairs, the same geometry under a different load, the same concept under a different process.
  • Hindsight relabelling: a design that misses 200 Hz but reaches 184 Hz is a valid answer to a 180 Hz request.
  • Honest splits: whole request types are held out for testing and frozen before any generation.
  • First-release targets: about 300 synthetic projects, about 10,000 designs verified at L1 and about 500 at L2, and 500–2,000 agent trajectories, set by the token budget.
In AI terms

Every record is a supervised example (geometry plus conditions → physics). When an agent made it, it is also a trajectory (state → action → result). Hindsight relabelling works like hindsight experience replay. Held-out request types make the tests measure out-of-distribution generalisation.

9Learning

Physics AI

It is trained in stages: static loads, then natural frequencies, then random vibration, then heat, then combined physics.

ModelLearnsUsed for
Fast predictorProgram, geometry and specification → mass, frequencies, vibration response, fatigue, stress, temperature, pass/failScreening thousands of candidates
Mesh modelMesh graph and loads → displacement, stress, mode shapes, temperature fields. Modes are matched before computing the loss, because they swap order between similar designsHot spots and diagnosis
EmbeddingAll designsSimilar-design search, novelty, detecting unfamiliar designs
Design proposerRelabelled specification → program pairsNearly-right starting designs
Validity mapsL0 against L1 against L2 on every designEvidence-based rules for which model to trust

Training adds physics-consistency losses (equilibrium, the eigenproblem, energy) to the data loss, and uses ensembles for uncertainty. A domain gate sends anything unfamiliar straight to FE.

The LLM

It learns five capabilities:

  • extracting a specification and detecting what is missing;
  • planning a campaign;
  • choosing tools;
  • diagnosing failures;
  • knowing when not to trust the physics AI.

Training runs in four stages:

  1. supervised fine-tuning on requests, states and actions, diagnoses and recoveries;
  2. preference tuning: a good action against a merely plausible one;
  3. training on whole trajectories;
  4. optionally, reinforcement learning, with the reward computed from verified physics only.

The model is a small open-weight model trained with LoRA on a paid cloud GPU, and it is evaluated against the Claude-driven agent on held-out tasks.

In AI terms

This is reinforcement learning with verifiable rewards, where the verifier is physics. The reward never comes from the surrogate, which would invite reward hacking, and winning designs are re-checked at full fidelity. Distilling search results into the policy and repeating is expert iteration.

10A request at runtime

Example: "Mount a 1.2 kg, 15 W control module to a vertical body rail. ISO 16750-3. First mode ≥ 200 Hz, module base ≤ 85 °C. Lightest possible."

  1. Request. Plain language, plus a short form that shows the numbers extracted from it.
  2. Specification check. Gaps are filled from the program context and flagged. Only the questions that block progress are asked. Nothing unspecified is claimed.
  3. Characterise. The required stiffness is k = m(2πf)² ≈ 1.9 kN/mm, and the thermal budget is 20 K for 15 W, about 1.3 K/W. These numbers show which requirement binds.
  4. Campaign. Concepts are proposed with their physics reasons. Isolation is ruled out here because it cannot meet a frequency floor.
  5. Generate. Candidates are produced with their lineage and pass through the manufacturing-rule checker.
  6. Screen. Physics AI scores candidates, with uncertainty and the domain gate.
  7. Select. A mix of the best predicted, uncertain, novel, near-boundary and diverse candidates.
  8. FE, diagnosis, edit. The LLM picks the strategy and the optimiser picks the numbers. Steps 5–8 repeat.
  9. Verify the finalists at L2 and build the evidence package.
  10. Export. An editable FreeCAD file, STEP, a flat-pattern DXF, a drawing and the report.

After training, the parser asks fewer questions, the proposer starts closer to a passing design, and the predictor screens faster. FE still proves every design. Runtime results join the training pool only after verification.

11Scoring and reference solutions

Proposed in discussion · not yet in the written plan
LevelWhat qualifiesUsed for
ValidPasses every check at L1 with a VALID trust labelDataset labels, training
VerifiedValid, plus a pass at L2, robust across the uncertainty ranges (damping, joint stiffness, tolerances), and agreement with a second solverAnything shown or claimed
ReferenceThe best verified design found by a deliberately thorough search, with the search budget recorded. It is frozen and tied to the grader versionScoring agents
  • "Best" means best known. When an agent beats a reference and its design is verified, it becomes the new reference.
  • Hand work goes into five places:
    • a conventional baseline per task, sized the way an experienced engineer would;
    • exact textbook answers that verify the grader;
    • engineer review of sampled references;
    • proofs for impossible tasks;
    • physical tests.
  • Agents are scored on:
    • whether every requirement passes;
    • the gap to the reference on the objective;
    • the gain over the conventional baseline;
    • pass@1, pass@k and pass^k over at least five repeats.
    Geometric similarity to the reference is never scored, because a design problem has many good answers.
  • References for held-out tasks are sealed, and all references are re-graded whenever the grader changes.

12Showing creativity

  1. Concept atlas. One request fills a live gallery of genuinely different passing brackets.
  2. The invention moment. The archive shows an empty region. The agent explains mechanism → principle → feature, writes the operation, passes the gate and FE, and the pipeline fills the region.
  3. Beads placed by physics. The strain energy of mode 1 is shown, beads go along it, and the frequency jumps. A rule-of-thumb bead is shown alongside for comparison.
  4. Strategy as well as shape. For a vibration-sensitive sensor, the agent isolates instead of stiffening, and explains why.
  5. Novel-and-better scoreboard. Feasibility, performance and novelty are measured, not asserted.
  6. Rules nobody wrote down. Design patterns mined from the dataset.
  7. Real parts. Tap-tested, with the measured first mode shown next to the prediction.
  8. From request to a laser-ready DXF in minutes.

13Principles

  • Verified only inside a resolved project context. That means a request, the program's context and a specification. A concept mode may work from rough numbers, but its results are never labelled verified.
  • FE is the authority. Physics AI screens, the LLM chooses strategy, and the optimiser chooses numbers.
  • Nothing unverified becomes training truth.
  • Agents act only through typed tools. Their own code enters only through the gate.
  • Rules live in retrieval, not in weights.
  • The LLM sees a compact engineering state.
  • Every claim is reproducible: one commit, one config, manifests with every setting.
  • An independent build. Learnings from other repositories are cited. Their code is copied only when a step needs it, at the smallest unit (a function, a module, or a whole file only when needed), never in bulk, with its origin recorded and a test.

16Decisions

Made, 5 October 2026

  • Sheet-metal brackets (structural mechanics and vibration) for the public demo.
  • All three deliverables in full, including LLM fine-tuning.
  • FreeCAD's sheet-metal workbench as the builder, with CadQuery only as a fallback.
  • The specification is given as numbers: no design volume, CAD optional.
  • Designs are called verified only inside a resolved project context.
  • An independent build that copies code only when needed, at the smallest unit.

Open, with a recommendation

  • Generation approach and sources as described here. Recommended.
  • The engineer's reference architecture as the basis. Recommended; the plan already follows it.
  • Heat in version 1. Recommended at L0 and L1.
  • Shell or solid elements. To be decided by benchmark.
  • A cross-solver check against the DeepJEB dataset. Recommended, on static load cases.
  • Vibration profiles. Buy ISO 16750-3, or use MIL-STD-810H, which is public.
  • Licences. Apache-2.0 for code, CC BY 4.0 for data.
