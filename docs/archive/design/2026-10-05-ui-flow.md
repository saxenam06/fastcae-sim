# UI flow: a new bracket request, screen by screen

*Draft, 2026-10-05. Companion to `2026-10-05-end-to-end-walkthrough.md` (Phase 3, example A, and Appendix A).
The screens are sketches of content and flow, not a visual design. All numbers are illustrative.*

**The request:** *"Mount a 1.2 kg, 15 W control module to a vertical body rail. ISO 16750-3. First mode ≥ 200 Hz,
module base ≤ 85 °C. Sheet metal, lightest possible."* The user also attaches three STEP files: the rail, the module
and the allowed envelope.

**The key idea.** The system has never seen this rail or this module.
- **Screens 2 and 3** turn the user's CAD into the same numeric interface description that the factory generates for
  its own requests.
- **From screen 4 on**, a user request and a factory request follow exactly the same path.

---

## Screen 0: set up once per company (not per request)

The company profile holds:
- materials and gauges in stock;
- processes (e.g. laser cutting and press brake, sheet ≤ 3 mm);
- fasteners and joining methods available;
- standards and design rules;
- default ambient temperatures by mounting location.

It is set up once and reused for every request.

## Screen 1: new request

```
NEW BRACKET REQUEST
────────────────────────────────────────────────────────────────────────
Describe the part
  Mount a 1.2 kg, 15 W control module to a vertical body rail.
  ISO 16750-3. First mode ≥ 200 Hz, module base ≤ 85 °C.
  Sheet metal, lightest possible.

Attach CAD        rail.step (attached)   module.step (attached)   envelope.step (attached)
Company profile   Body electronics: materials, gauges, joining, rules

                                                               [ Start ]
```

**You:** type the request, attach the three files, press **Start**.

## Screen 2: reading your CAD (automatic, a few seconds)

```
READING CAD
────────────────────────────────────────────────────────────────────────
rail       3 through-holes, Ø 6.6 mm (M6 clearance), 80 mm apart, on a flat land facing the envelope
module     4 threaded holes, M5 (Ø 4.2 tap drill), on a 100 × 70 mm pattern; base face 120 × 90 mm
envelope   140 × 100 × 90 mm, with 1 keep-out (wiring harness)
axes       X forward, Y left, Z up (from the files' coordinate frame)
vs text    1 choice and 2 gaps to resolve → next screen
```

**Behind the scenes:** tools import the files and check their units and validity. They then:
- find the holes, faces and patterns;
- read the vehicle axes;
- compare what they found with your text.

## Screen 3: check the brief (you confirm)

This is where a new request's unknown interfaces get settled.

```
CHECK THE BRIEF
────────────────────────────────────────────────────────────────────────
3D view highlights
  rail holes H1, H2, H3           blue      click a hole to include or exclude it
  rail contact land               blue
  module bolt holes (4)           green
  module base (heat face)         orange
  envelope / keep-out             grey / red
  vehicle axes                    arrows

Specification                Value                          Source
  payload mass               1.2 kg                         your text
  heat                       15 W                           your text
  rail bolts                 H1, H2, H3 ?                   CAD             ← question 1
  module bolts               4 × M5                         CAD
  module centre of gravity   ?                              —               ← question 3
  vibration profile          ISO 16750-3, which one?        your text       ← question 2
  first mode                 ≥ 200 Hz                       your text
  module base temperature    ≤ 85 °C                        your text
  ambient temperature        65 °C                          company default (change?)
  material, process          Al 5052-H32, sheet ≤ 3 mm      company profile
  damping                    2–5 %, worst case used         default, flagged

Questions
  1  The rail has 3 M6 holes within reach.   [ Use all 3 ]  [ Let the design decide ]  [ Pick… ]
  2  Which ISO 16750-3 profile?              [ Body ]  [ Engine ]
  3  Module centre of gravity?               [ CAD centroid, uniform density ]  [ Enter value ]

                                                         [ Confirm brief ]
```

**You:** answer the questions, correct anything wrong (click a hole, edit a value), then press **Confirm brief**.

**Result:** a complete, typed specification. Every value is recorded with where it came from: your text, the CAD,
the company profile or a default. It has the same format the factory generates for itself.

## Screen 4: plan and analysis set-up (you approve)

```
PLAN
────────────────────────────────────────────────────────────────────────
Concepts to try    1 channel + beads     2 closed box     3 hat section
Ruled out          isolation: it cannot meet a first-mode floor of 200 Hz

Every candidate is analysed the same way
  supports     clamped zones at the rail bolts (washer footprint + compression cone)
  payload      1.2 kg at the centre of gravity, coupled at the 4 module bolts
  vibration    ISO 16750-3 body profile in X, Y and Z separately; shock; gravity
  heat         15 W into the bracket through the module base; 65 °C ambient
  checks       first mode · random-vibration fatigue · shock · bolts ·
               temperature · sheet-metal rules · socket access for every bolt
  preview      the supports, payload coupling, heat input and keep-outs are
               highlighted on the first-guess bracket in the 3D view

Budget          about 15 min, at most 200 FEM runs
                                                      [ Edit ]    [ Run ]
```

**You:** check the boundary-condition preview, then press **Run**. You can also edit first, for example to add a
concept, change the budget or add a load case.

## Screen 5: design run (live; watch or leave it)

```
RUNNING    6 min · 212 designs tried · 31 FEM runs                    [ Pause ]
────────────────────────────────────────────────────────────────────────
Best so far    closed box, 49 g, smallest margin +9 %

Log
  channel        first mode 184 Hz (−8 %): bending at the upright root → add a diagonal bead
  channel+bead   212 Hz, passes → optimizing for mass
  closed box     236 Hz, passes → optimizing for mass → 1.2 mm, 49 g
  2 unfamiliar shapes → sent straight to full FEM

Chart    mass against smallest margin, one dot per graded design
Gallery  3D thumbnails of the candidates
```

**You can:**
- pause;
- comment in plain language, e.g. "try a hat section with a wider flange";
- stop the run.

**The agent pauses by itself** only for a decision it cannot make, e.g. *"No concept meets 85 °C without a thermal pad.
Allow one?"*

## Screen 6: results

```
RESULTS    3 candidates, all verified with full 3D FEM
────────────────────────────────────────────────────────────────────────
#  Concept                      Mass   Smallest margin          Novelty
1  closed box, 1.2 mm           49 g   +9 %   (first mode)      0.19
2  channel, mode-shaped bead    52 g   +7 %   (first mode)      0.47   new design
3  channel + 2 beads            55 g   +2.5 % (first mode)      0.05

Candidate 1    [ 3D ] [ flat pattern ] [ mode 1, 218 Hz ▶ ] [ stress ] [ temperature ]
  Check            Value      Limit       Margin   Model     Valid?
  first mode       218 Hz     ≥ 200 Hz    +9 %     L1 + L2   yes
  fatigue damage   0.29       ≤ 0.5       +42 %    L1        yes (broadband: Dirlik)
  shock stress     131 MPa    ≤ 154 MPa   +15 %    L1        yes
  module base      83 °C      ≤ 85 °C     +2 K     L1        convection ±25 %: worst case 84.6 °C
  sheet rules      all pass
  Assumptions      damping 2–5 % (worst case used) · rail rigid at the bolts · module rigid
```

**You:** inspect each candidate (3D model, flat pattern, animated mode shapes, stress and temperature plots) and
compare candidates side by side.

## Screen 7: refine in plain language

```
You     Lighter, and no spot welds: our line can't weld aluminium.
Agent   Switched the box seam to clinching and re-optimized: 51 g (+2 g for the clinch
        flange), smallest margin +8 %, verified with full FEM. Candidate 2 (52 g) is now
        almost as light. Keep both?
```

## Screen 8: approve and export

```
APPROVE AND EXPORT    candidate 1, version 2
────────────────────────────────────────────────────────────────────────
bracket.step          opens in NX or any CAD tool
flat_pattern.dxf      for laser cutting
report.pdf            every requirement → value → margin → model → assumptions
decision_log          every step the agent took, and why
analysis files        mesh and results
[ ] share this run to improve the system
```

## Who does what

| Screen | You | Claude | Tools |
|---|---|---|---|
| 1 New request | Type the request, attach CAD | — | — |
| 2 Reading CAD | Wait a few seconds | Compares the CAD with your text | Import, check, recognize holes, faces, patterns and axes |
| 3 Check the brief | Answer, correct, confirm | Asks only blocking questions | — |
| 4 Plan | Approve or edit | Proposes concepts and rules some out, with reasons | First-guess bracket, boundary-condition preview |
| 5 Run | Watch, steer, or leave | Decides each next step | Build, analyse, optimize, check |
| 6 Results | Compare candidates | Explains the trade-offs | Verify finalists with full 3D FEM |
| 7 Refine | Ask in plain language | Re-plans | Re-build and re-verify |
| 8 Export | Approve | Writes the report summary | Export the files |

**Factory versus user request.** A factory request skips screens 2 and 3, because the factory already has the
interface numbers. Once you press **Confirm brief**, both follow the same path.
